# Настоящая MissMaki-test: Anonymous Auth — 2 ноября 2026

## Выбран один механизм

Оставляем **Supabase Anonymous Auth**. Поддержка подтвердила Free, владелец включил режим, API `/auth/v1/settings` теперь возвращает `external.anonymous_users=true`. Две настоящие регистрации без почты и пароля получили отдельные сессии с `is_anonymous=true`. Это технические анонимные пользователи Auth; покупателю не нужно регистрироваться.

`database-token` больше не используется стандартной тестовой сборкой. Код альтернативы оставлен в истории/резерве, но fallback не включён. **003_guest_checkout.sql сейчас НЕ применять**: она закрывает старую функцию create_order для покупателей и поэтому несовместима с выбранным путём без отдельной миграции. Не удалять её объекты вручную, если она уже была применена. Реальная успешная отправка через create_order подтверждена на текущей базе, пересоздавать базу не требуется.

Anonymous Auth предпочтительнее здесь: встроенные UID, обновление токенов, RLS и Realtime, меньше собственной криптографии/гостевых серверных функций. Права кухни проверяются через staff. Анонимная сессия одного браузера не восстанавливается на другом устройстве; очистка хранения браузера лишает клиента доступа, но не удаляет заказ у кухни.

## Что действительно проверено на Татнет

Использован только проект MissMaki-test, публичный ключ и две вымышленные анонимные сессии. Без паролей или service_role. Секреты сессий не записывались в отчёт, logout обеих сессий вернул 204. Записи Auth сохраняются как технические следы теста.

- Две отдельные анонимные сессии и отсутствие роли staff у покупателя.
- Свободный слот тестового предзаказа, две одновременные отправки одного request_id: одна запись.
- **Заказ №3**, «АВТОТЕСТ ANONYMOUS — НЕ ГОТОВИТЬ», вымышленные телефон/адрес, 470 ₽, самовывоз. Остался **новым**: без staff нельзя принять/отклонить его. Сотруднику нужно отклонить вручную после проверки.
- Своя запись читается, чужая выдаёт пустой список, без сессии доступ запрещён.
- Прямое изменение статуса и изменение через order_status запрещены.
- Самоназначение admin запрещено.
- Подменённая цена и изменённое тело с прежним request_id отклонены.
- Обновление Auth-сессии и чтение прежнего заказа после него успешны.

Это **16 проверок реального API**, а не полный заказ из опубликованной страницы. Чтение собственной записи подтверждает сохранение в общей таблице кухни; появление в интерфейсе staff и реальная доставка Realtime ещё не проверены. Нет доступа к браузерной сессии администратора, повышать права тестовых покупателей не пытались.

## Состояние опубликованного тестового приложения

Адрес владельца: https://missmaki-site.tatnet.app/kitchen/ . Проверка HTTP 200 и опубликованного `/shared/config.js` обнаружила старую сборку: `guestMode: database-token`, `enabled: false`, пустые URL/key. Публичные параметры задаются отдельно в браузере владельца через /setup; агент к его localStorage доступа не имеет. Включение Auth не меняет опубликованный JavaScript.

Подготовлена новая стандартная сборка `npm run build:preview` с `guestMode: supabase-anonymous`. После обновления /setup игнорирует прежний выбор database-token в сохранённых публичных настройках и берёт механизм из новой сборки. Одновременно два механизма не вызываются. В диагностике отключён обход через вымышленные email-аккаунты.

## Действия владельца с iPhone

1. Татнет → **Приложения → существующее тестовое missmaki-site**. Проверить ветку **codex/missmaki-kitchen**, сборку **npm run build:preview**, папку **dist-preview**. Нажать **Пересобрать / Redeploy** после появления нового коммита. Не создавать проект/базу заново, не выбирать main и не привязывать missmaki.ru.
2. Открыть https://missmaki-site.tatnet.app/setup/ . Если параметры ещё не сохранены, ввести прежние публичные Project URL/key MissMaki-test → «Сохранить настройки». Пароль сюда не вводить. Обновить страницу кухни; при старой версии закрыть вкладку и открыть снова.
3. Войти существующим сотрудником на `/kitchen/` → «Проверка прав и времени» → запустить проверку. Новый сценарий должен называться **«Анонимные сессии двух покупателей»**, а не «Две гостевые сессии без регистрации в Auth».
4. Диагностика проверяет новый вымышленный заказ, изоляцию, все восемь времён, отказ и историю. Если ошибка — скопировать отчёт без паролей/токенов, не отключать RLS. Заказ диагностики при успехе остаётся отклонённым.
5. На втором устройстве/в отдельном браузере открыть тестовый магазин `/`, оформить вымышленный предзаказ. В кухне нажать **15 минут**. У покупателя проверить «Ваш заказ №… принят! Время ожидания — 15 минут». Повторить потерю сети/перезагрузку и звук. Старый №3 можно отклонить: его тестовые сессии агент уже завершил.
