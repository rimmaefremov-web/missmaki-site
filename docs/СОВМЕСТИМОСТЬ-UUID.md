# Совместимость UUID и ошибки оформления

Все 11 браузерных вызовов randomUUID в заказах, намерениях киоска, отзывах, подписках, резервных копиях и диагностике используют MMCompat.uuid. Служебные Node.js-тесты продолжают пользоваться node:crypto. Вендорная библиотека Supabase не изменена.

Единый исходник shared/compat.js использует native randomUUID, если он доступен, иначе — 16 криптографически случайных байтов getRandomValues с битами UUID v4/variant. Math.random не используется. При отсутствии безопасной криптографии заказ не отправляется, показывается русская инструкция открыть HTTPS в Safari/Chrome.

Для закэшированных страниц также устанавливается безопасный polyfill отсутствующего randomUUID. API-entry содержит точную генерируемую копию общего исходника: `node scripts/build-api-compat.mjs`. Автотест проверяет совпадение. Это позволяет новому API обслуживать HTML, закэшированный до появления отдельного compat.js.

На рабочих HTTP-адресах missmaki.ru и www.missmaki.ru выполняется переход на HTTPS с сохранением пути/параметров/якоря. Киоск загружает защиту до iframe. Локальные и тестовые HTTP-адреса не перенаправляются. Сертификат GitHub проверен внешним TLS-анализатором: доверенная цепочка для Apple/Android на всех четырёх IPv4. Настройка Pages Enforce HTTPS кодом не отключается.

Ошибки покупателю проходят через общий русскоязычный обработчик; исключения JS, undefined и технические коды не показываются. Сохраняются корзина, requestId и clientIntent при сбое/перезагрузке. Новое намерение появляется только после подтверждённой отправки предыдущей покупки.

Проверки: unit-тесты UUID v4/случайности/масок/отсутствия слабого fallback, нативного API, ошибок и HTTPS-перехода. Общие браузерные тесты оформляют все четыре типа через сайт/киоск с выключенным native randomUUID и локальными SQL-функциями. Матрица playwright.compat.config.cjs проверяет WebKit iPhone, Chromium Android и моделируемые UA встроенных браузеров с отключённым API, включая потерянный ответ и повтор с прежним requestId.

WebKit/мобильные профили — автоматизированная эмуляция, не физический iPhone и не запуск реальных приложений соцсетей. Рабочую базу, SQL и тестовые заказы №22/№23 это исправление не меняет.
