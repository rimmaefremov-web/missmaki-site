# Самовывоз без имени и телефона — миграция 009

Подготовлено для существующей MissMaki-test. Рабочий сайт не переключать до установки 009 и проверки API. Публичный ключ не позволяет применить SQL, административного подключения у агента нет. Проверка API показала, что checkout_capabilities ещё отсутствует (PGRST202).

## Одно действие владельца

В MissMaki-test → SQL Editor → New query вставить целиком `supabase/INSTALL_OPTIONAL_PICKUP_009.sql` и нажать Run. Не создавать базу, не повторять 001–008, не запускать полный INSTALL_FINAL.sql. Ожидаемый результат: migration=009, installed=true, selfChecks=passed, testRecordsPersisted=false. При ошибке ничего не публиковать; передать текст ошибки, пароль не нужен.

Файл устанавливает изменение и выполняет проверки в одной транзакции. При ошибке изменение отменяется. Проверки используют существующих пользователей, не создают Auth-аккаунты. Все служебные заказы, записи истории, изменения ячеек и временное отключение бюджетного триггера откатываются. Настоящие записи не удаляются. PostgreSQL может оставить обычные пропуски номеров после отменённых тестовых вставок; последовательности намеренно не перематываются. Вне часов работы обычные заказы проверяются до ожидаемого отказа по времени работы; предзаказы проверяются полностью. Результат содержит businessHoursOpen.

После подтверждения результата агент проверит публичный read-only RPC checkout_capabilities, затем объединит подготовленный PR и проверит публикацию. До этого main остаётся прежним; тестовый сайт может уже показывать подготовленную форму, но сервер не примет пустые контакты до 009. Нельзя считать установку завершённой по наличию файла в GitHub.

## Что меняется

Обычный самовывоз и предзаказ на самовывоз допускают пустые, отсутствующие и частично заполненные контакты. Предоставленные значения проверяются по длине/формату. В таблице сохраняются пустые строки, а карточка кухни не рисует пустые контактные строки/ссылки. Номер заказа остаётся заголовком.

У доставки и предзаказа на доставку имя, телефон, район и адрес обязательны. Пробельные строки не заменяют обязательные данные. Цены, количество, антиспам, RLS, идемпотентность, время работы, расписание, ячейки, подтверждения и звук сохраняются. Киоск использует ту же форму без изменения kiosk-файлов.

## Проверки

`tests/optional-pickup.test.cjs`: все четыре варианта с реальными локальными SQL-функциями, получение сотрудником, подтверждение/отказ, сохранение расписания, ячейки, приватность, пустые/отсутствующие/частичные контакты, обязательные поля доставки, лимиты, повтор установки и откат тестов.

`tests/browser/optional-pickup.spec.cjs`: сайт и киоск, оба способа получения и оба режима времени, передача формы в локальный PostgreSQL, карточка кухни и автоматические сообщения клиенту. Запускается в эмуляциях телефона, планшета и компьютера. Это не испытания настоящих заказов на планшете владельца.

Для двух последовательных покупателей киоска с одинаковой корзиной используется отдельный clientIntent: новый после подтверждённой отправки, прежний при сбое/повторе. Это предотвращает склейку разных анонимных самовывозов старой защитой от дублей; лимиты и авторизация не ослабляются.

Итог текущей проверки: 69/69 автоматических и 99/99 браузерных тестов прошли. Ещё 2 проверки повторной одинаковой покупки на телефоне прошли отдельно. Использованы фикстуры и локальная PostgreSQL с исходными SQL-функциями; для обычных заказов в CI задан локальный тестовый час 15:00. Реальная MissMaki-test не изменялась. Публикация main не выполнена, ожидается установка 009.
