# Единый выпуск MissMaki с ячейками — 4 ноября 2026

Владелец утвердил 008 и разрешил отправить изменения в существующую ветку и обновить тестовый сайт. Это не разрешение публиковать missmaki.ru или объединять PR. Новая база/платный тариф не создаются.

## Один пакет, одно переключение

Текущий выпуск включает проверенную кухню, Anonymous Auth с серверной проверкой/лимитами, отзывы/модерацию, звук, зашифрованные копии и ячейки 1–6 для обоих видов самовывоза. Базовый пакет без 008 от 4 ноября заменён этим общим выпуском. Старые инструкции `seal-release` для выпуска без ячеек больше не являются путём его публикации.

`prepare-launch.mjs` создаёт candidate/ и safe-fallback/ из одной текущей версии, сохраняет меню/цены/фото, включает database/INSTALL_PICKUP_008.sql и полный установщик для справки. Действующей базе с установленными 004–007 нужен **только INSTALL_PICKUP_008.sql**. Полный установщик и 001/002/003 повторять не надо.

Манифест отдельно хранит уже проверенную основу и ещё не установленную 008: подтверждение первой копии владельцем учитывается, установка/живые проверки ячеек не выдаются за выполненные. До успешной установки и отдельного согласия публикация остаётся заблокированной. Новая копия/новый пароль/настройки Supabase сейчас не требуются.

## Единственное действие владельца

В **существующей MissMaki-test → Studio → SQL Editor → New query** вставить целиком готовый **supabase/INSTALL_PICKUP_008.sql** и нажать **Run один раз**. Ничего не редактировать. Это необходимо, потому что у агента есть публичный ключ, но нет административного подключения для исполнения SQL.

Файл выполняет 008 и встроенную проверку в одной транзакции. Проверяет общий цикл, обычный/предзаказанный самовывоз, все 8 времён, повторное подтверждение, сохранение даты/времени, доставку и отказ без номера. Служебные записи и изменения счётчика откатываются; настоящие заказы/пользователи не удаляются. Клиентские номера заказов проверка не расходует; внутренние номера событий audit могут иметь обычные для PostgreSQL пропуски после rollback. При ошибке установка отменяется целиком — не запускать фрагменты; при оставшейся открытой транзакции выполнить ROLLBACK и передать только текст ошибки.

В конце ожидается строка результата с migration=008, installed=true, selfChecks=passed, testRecordsPersisted=false. Параметры Auth, admin/UID, тариф и содержимое настоящих заказов не меняются. Счётчик при повторе файла не обнуляется.

После сообщения об успехе агент проверит доступность новой схемы API. Публикация основного сайта — только после отдельного явного разрешения, одним согласованным релизом с готовым откатом. Тестовый frontend до установки совместим со старой базой; ячейки появятся при подтверждениях после 008. Уже подтверждённые старые заказы без номера автоматически не перенумеровываются.

## Ограничения

Это не гарантия от DDoS или неограниченной работы Free. Копии бизнеса ручные, полный backup Auth не заявлен. Серверный self-check не является нагрузочным испытанием независимых HTTP-подключений. Записи теста откатываются, Realtime не должен доставлять их планшету. В рабочий домен, DNS, main и PR merge агент без разрешения не вмешивается.

## Проверки текущей версии

57/57 автоматических тестов и 63/63 браузерных сценария прошли, npm run build:preview успешна. Клиентские тексты/ячейки/дата/время и прежние функции покрыты регрессией. В установщике проверены первый запуск, повтор с уже использованным счётчиком, отсутствие новых Auth-пользователей/заказов/аудита и сохранение последовательности клиентских номеров. Ошибка отсутствия admin откатывает установку. Эти локальные результаты не выдаются за исполнение на настоящей базе.
