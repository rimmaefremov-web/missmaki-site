# Новый пароль существующему администратору — iPhone

Ошибка Studio «The object cannot be found here» сама по себе не означает, что пользователя нет. Не удаляйте пользователя и не создавайте другого: новый UID потеряет связь с существующей ролью staff. SQL для замены encrypted_password не используем: пароль может попасть в историю SQL/журналы, а прямое изменение обходит штатный процесс Auth.

Подготовлена отдельная страница `/kitchen/access.html`, использующая поддерживаемые Supabase Auth `resetPasswordForEmail` и `updateUser`. Она войдёт только в тестовую сборку. Не нужны SQL, миграция 003, anonymous sign-in или секретные ключи. UID, email и staff/admin не изменяются. Новый пароль отправляется напрямую в HTTPS Auth вашей тестовой базы, не сохраняется кодом страницы, токены восстановления держатся в памяти. Копировать ссылку из письма в чат нельзя.

## 1. Подготовить тестовый адрес

Если отдельного тестового адреса ещё нет, сначала выполните инструкцию [АДМИН-IPHONE-FREE.md](АДМИН-IPHONE-FREE.md). Ветка `codex/missmaki-kitchen`, команда `npm run build:preview`, папка `dist-preview`. Никаких изменений missmaki.ru/DNS или объединения PR. Если тестовое приложение уже есть, обновите его сборку из этой ветки.

## 2. Разрешить возврат из письма — только MissMaki-test

1. Safari → кабинет Татнет → **MissMaki-test → Studio → Authentication → URL Configuration** (в другой версии: Settings → URL/Redirect URLs).
2. В **Redirect URLs / Additional Redirect URLs** добавьте **точный HTTPS-адрес вашей тестовой страницы**, заканчивающийся `/kitchen/access.html`. Возьмите адрес опубликованного приложения, не выдумывайте домен, не используйте wildcard `*`.
3. Сохраните. Существующие адреса не удаляйте; **Site URL не меняйте**. Это единственная необходимая настройка Auth для возврата; автоматически я её не меняла.
4. Если этого раздела нет/нет прав — не запускайте SQL для изменения Auth. Нужна помощь Татнет с allowlist redirect. Пароли и SMTP-секреты в чат не присылайте.

## 3. Получить ссылку и ввести пароль

1. На том же iPhone откройте тестовый адрес → `/setup/`. Проверьте публичные настройки **MissMaki-test** (Project URL и publishable key). В готовом подключённом архиве они уже есть. Пароль сюда не вводится.
2. Откройте `/kitchen/access.html` на этом же тестовом адресе. Введите **почту существующего администратора** → «Получить ссылку на почту».
3. Откройте письмо Supabase/Татнет, проверьте, что вы сами только что его запросили → нажмите ссылку. Откройте в обычном Safari, на том же тестовом домене. Если открылось встроенное окно Почты, выберите открыть в Safari. Не используйте «Частный доступ», если настройки были сохранены в обычном Safari.
4. После сообщения «Ссылка проверена» введите новый уникальный пароль дважды → «Сохранить новый пароль». Пароль рекомендуется сохранить в приложении Apple «Пароли». Не отправляйте его мне и не делайте скриншот с паролем/полным адресом ссылки.
5. После сообщения об успехе откройте `/kitchen/`, войдите существующей почтой и **новым паролем**. После восстановления запрашивается выход остальных сессий; уже выданные access-токены могут работать до своего истечения.

## Если письмо не пришло

Проверьте «Спам» и адрес. Сообщение «Запрос принят» не доказывает доставку или наличие пользователя — Auth скрывает это намеренно. Не нажимайте многократно: действуют ограничения отправки. Встроенный SMTP может иметь ограничения и не доставлять письма на произвольные адреса. Изменённый шаблон письма также может игнорировать redirectTo.

Если письма нет либо ссылка ведёт не на тестовую страницу, отправьте поддержке Татнет: «В MissMaki-test карточка существующего пользователя выдаёт The object cannot be found here. Нужна штатная recovery-ссылка для существующего пользователя с возвратом на [точный адрес тестовой страницы], без удаления пользователя или изменения UID. Проверьте SMTP, recovery template и Redirect URLs». Укажите почту только в защищённом обращении поддержки. Не пересылайте ссылку восстановления или токены в чат.

Административный API `auth.admin.updateUserById` тоже поддерживается Supabase, но требует секретного серверного ключа и доверенного серверного интерфейса. Такого интерфейса здесь нет: ключ в браузер/SQL/чат помещать нельзя. Поэтому обещать восстановление без работающей почты или помощи провайдера нельзя.

## Проверки

Код подготовлен и тестируется локально. Реальная отправка recovery-письма, шаблон письма, переход Safari и смена пароля в Татнет пока не проверены. Пароль и настройки Auth автоматически не менялись. Исходный рабочий сайт сохранён.

Справка Supabase: https://supabase.com/docs/reference/javascript/auth-resetpasswordforemail и https://supabase.com/docs/reference/javascript/auth-updateuser . Это поддерживаемые API Supabase; совместимость конкретной установки Татнет требует испытания.
