# Проверка реальной системы перед запуском

Для новой гостевой схемы использовать отдельную MissMaki-test после миграции 003. Anonymous Sign-ins больше не требуется. Проверить токены, серверную вычислительную защиту и квоты; протокол: ГОСТЕВЫЕ-ЗАКАЗЫ-FREE.md. Это не разрешение переключать production.

Выполнять на staging с настоящим Supabase, без реальных персональных данных. Включённые mock-тесты не закрывают эти пункты. Ответственный отмечает дату и результат каждого пункта. В этой задаче реальные пункты **ещё не выполнены**.

- [ ] Два разных покупателя в разных браузерах и сотрудник на планшете; у покупателя нет доступа к /kitchen данным и чужому UUID заказа через API.
- [ ] Оформить доставку и самовывоз. Сверить все поля, цены каждой вариации меню, доставку 200/0 ₽, подарок от 1000 ₽ и оплату при получении.
- [ ] Новый заказ записан в БД, получил номер, виден на кухне. Проверить звук после нажатия «Включить звук».
- [ ] По очереди 15, 30, 45, 60, 90, 120, 150, 180 минут. Покупатель видит точный номер и время без обновления; кухня показывает «Принят».
- [ ] Отказ сохраняется в истории, клиент видит отказ.
- [ ] Два сотрудника одновременно меняют один заказ: второй получает сообщение о конфликте, история не теряется.
- [ ] Два покупателя одновременно отправляют разные заказы: уникальные номера, оба видны. Два клиента на один слот предзаказа: проходит только один.
- [ ] Двойное нажатие, повтор с тем же ID, потеря ответа после COMMIT: в БД одна запись. С перезапуском браузера восстановить неподтверждённый черновик и повторить.
- [ ] Отключить интернет на кухне, оформить заказ с другого устройства. Кухня предупреждает об отсутствии связи; после возврата интернета заказ появляется.
- [ ] Перезагрузить планшет: сохранённые заказы и статусы на месте после входа. Не считать офлайн-оболочку получением новых заказов.
- [ ] Подменить цену, SKU, количество, итог и статус через DevTools/API: операция отклоняется, цены считает сервер.
- [ ] Создать отзыв с отдельным согласием. В админке pending, в публичной выдаче отсутствует. Принять: approved, опубликован у всех и у автора.
- [ ] Другой отзыв отклонить: в админке rejected, публично отсутствует. У автора «Ваш отзыв ожидает подтверждения» до и после перезагрузки. Проверить прямой REST-запрос, public_reviews и my_reviews.
- [ ] История модерации содержит автора действия и оба статуса. Покупатель не может менять moderation или staff.
- [ ] Отключить сотрудника: новый запрос запрещён, данные убраны из панели. Проверить выход и повторный вход.
- [ ] Подтвердить российское размещение API/Auth/БД/резервных копий/журналов и поручение обработки. Проверить anonymous sign-in в выбранном сервисе.
- [ ] Проверить серверную защиту по IP и от перебора без зарубежной CAPTCHA; Cloudflare Turnstile в российском профиле запрещён.
- [ ] Восстановить всю базу вместе с Auth и историей в отдельный тестовый ресурс, проверить выгрузку для переезда и согласовать цену резервирования. SLA S3 не считать SLA Supabase.
- [ ] Физические iPhone Safari, Android Chrome, iPad Safari/PWA и компьютер: вход, заказ, изменение статуса, размеры кнопок, поворот экрана, восстановление связи, разрешённый звук.
- [ ] Заблокировать экран и записать реальные ограничения уведомлений. Push здесь не настроен.
- [ ] Проверить резервную копию и восстановление в отдельный проект, права после восстановления, мониторинг и согласованное удаление ПД.
- [ ] Запустить скрипт переключения, проверить юридические тексты, staging и отсутствие запросов Telegram/Google Apps Script. Проверить главную, контакты, меню, фото, корзину и юридические ссылки.
- [ ] После публикации проверить missmaki.ru/kitchen/, выполнить один согласованный тестовый заказ, обновить старые вкладки и отключить внешние старые обработчики без потери ранее принятых заказов.
