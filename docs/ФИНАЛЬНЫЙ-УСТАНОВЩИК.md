# Финальный установщик для существующей MissMaki-test

Рабочий домен/PR не переключены, платных ресурсов и новых баз нет. **INSTALL_FINAL.sql агентом не выполнялся:** нет административного подключения, только публичный ключ. API на момент read-only проверки не публикует новую функцию auth_signup_challenge; публичных отзывов 0.

## Одно необходимое действие владельца

В **MissMaki-test → Studio → SQL Editor → New query** вставить целиком **supabase/INSTALL_FINAL.sql** → **Run один раз**. Ничего не редактировать. 001/002 уже установлены; 003 не применять. Пакет объединяет повторяемые 004–007 одной транзакцией. При ошибке не запускать кусками: выполнить ROLLBACK, если редактор оставил транзакцию открытой, и передать только текст ошибки без секретов. Пароли/UID/admin не меняются. После Success сообщить результат: агент продолжит реальную проверку API. До этого новая защита и backup не считаются установленными.

## Серверная защита

004 устраняет повторную запись одинакового решения модерации. 005 ограничивает общие успешные вставки: заказы 10/мин и 200/сутки, отзывы 5/мин и 100/сутки независимо от UID.

006 проверяет при создании анонимного пользователя подписанную вычислительную задачу: HMAC-SHA256, 18 бит работы, срок 120 с, одноразовый nonce. Браузер решает её локально в Worker, зарубежной CAPTCHA нет. Прямой anonymous signup без решения отклоняется БД. Общий предел **всех новых пользователей**, включая email: 60/час и 300/сутки; смена вида регистрации не обходит бюджет. Metadata ограничены 8 КБ при вставке/изменении. Уже существующие сессии/пароли и вход сотрудника сохраняются. Перед SQL клиент работает прежним Anonymous Auth; после установки получает challenge автоматически. Production-кандидат требует защиту и не отправляет заказ без неё. Database-token не включается.

Лимиты — фиксированные окна, суточные UTC; могут задержать реального покупателя в пик/при атаке. Это ограничение роста/вычислительная защита, **не гарантия от DDoS**. Нужны контроль квот Free и резервный приём по телефону. Реальная совместимость триггера auth.users с версией/правами Татнет ещё требует испытания; пакет откатывается целиком при ошибке.

007 добавляет снимок данных для admin и обратимую отметку теста. Тестовый отзыв скрыт из публичной выдачи/прямого SELECT покупателя, автор видит pending; тестовые заказы исключены из рабочей очереди/звонка и остаются в истории. Признак меняет только staff. Автоматически отмечаются лишь два точно известных синтетических request_id №3/№4 с проверкой имени; реальных записей не удаляем и по похожим именам не скрываем. Остальные тесты можно отметить кнопкой в кухне. Диагностический сценарий отмечает свой заказ автоматически.

## Бесплатная копия заказов и восстановление

В кухне ссылка **«Резервная копия»**. После установки администратор вводит и повторяет пароль (от 12 символов) → «Создать зашифрованную копию». Один серверный STABLE RPC возвращает согласованный снимок заказов, отзывов и аудита. AES-256-GCM/PBKDF2-SHA256 (310000 итераций, случайные соль/IV) шифрует файл в браузере. Пароль не сохраняется и не отправляется серверу.

Сохранять ежедневно и перед релизом в «Файлы → На моём iPhone/iPad» либо защищённое хранилище РФ, не автоматически в iCloud. Пароль хранить отдельно. Это **ручная копия данных бизнеса**, не обещание фонового backup: браузер сообщает только подготовку загрузки, физическую запись файла нужно проверить.

Для восстановления на той же странице выбрать файл, ввести пароль → «Проверить файл и подготовить SQL». Расшифровка локальная, файл/пароль никуда не загружаются. SQL предназначен **для той же базы с сохранившимися Auth UID и схемой**: проверяет UID, добавляет отсутствующие записи, не удаляет и не перезаписывает существующие ID/статусы. Владелец запускает полученный SQL в SQL Editor, предварительно сохранив актуальную копию. Он содержит ПД: не отправлять в GitHub/чат, удалить после применения.

В транзакции импорта временно выключаются только два новых бюджетных триггера, затем включаются обратно. RLS/внешние ключи не отключаются. Конфликт номера/слота или отсутствие UID отменяют операцию — не продолжать кусками. Счётчики номеров не откатываются назад.

**В файл не входят пароли/токены Auth и весь кластер.** После уничтожения базы эта копия не восстановит учётную систему: нужна отдельная копия Auth у Татнет. Не создавать пользователей заново вместо восстановления UID. Пока полного снимка нет, не заявляем полную аварийную восстановимость.

## Проверки и границы готовности

44 автоматических теста и 57 браузерных сценариев прошли локально: реальные SQL/роли в PGlite, HMAC/proof/replay/квоты/metadata, admin-only экспорт, шифрование/неверный пароль, исполняемое восстановление с сохранением текущего решения и возвратом отсутствующей записи, приватность тестовых отзывов, совместимость старой базы, logout, заказы/меню/цены/звонок/сеть/отзывы. Браузерные API/Auth моделируются; это не доказательство установки на Татнет. Физическую работу кухни владелец проверил ранее.

Кандидат и аварийная версия собираются отдельно. Меню/цены/фото/корзина сохраняются; неправильное подтверждение отправки не выдаётся, прежний Telegram/GAS не возвращается автоматически. Пределы Free, инфраструктурный backup Auth и полнота локализации/правовой документации не подтверждаются публичным ключом. Не публикуем обещаний неограниченной доступности/полного соответствия вместо фактической проверки. Переключение missmaki.ru — только после отдельного разрешения.
