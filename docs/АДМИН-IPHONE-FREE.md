# Тестовый вход администратора с iPhone

Форма входа готова в `/kitchen/`. Используется уже созданный вами пользователь + роль admin в staff. Нового общего пароля нет, и присылать существующий пароль в чат не требуется. Вход и просмотр старых тестовых заказов не требуют anonymous-входа или миграции 003; новая гостевая диагностика требует 003.

**Публичная тестовая ссылка пока не опубликована.** Здесь есть только публичные настройки базы, а они не дают права создавать приложение в кабинете Татнет. Подготовлены готовый архив и сборка из Git. Ни платный ресурс, ни приложение от вашего имени автоматически не создавались.

## Отдельная бесплатная публикация из текущей ветки

Ниже — настройки по публичной документации Татнет; конкретный интерфейс вашего кабинета ещё не проверен. Если предлагается оплатить услугу, ничего не оплачивайте и остановитесь.

1. Safari → min.tatnet.ru → раздел **Приложения / Apps** → создать **новое** приложение. Имя: **MissMaki-test-preview**. Не открывайте настройки работающего сайта.
2. Выберите **Free / Бесплатный**, именно **статический сайт** (без backend, SSR, Docker или Edge Functions).
3. Подключите GitHub-репозиторий **rimmaefremov-web/missmaki-site**. Ветка — **codex/missmaki-kitchen**, не main. PR объединять не нужно.
4. Укажите тип **Static / Статический / Other**. Команда сборки: **`npm run build:preview`**. Папка результата: **`dist-preview`**. Если нужны установка зависимостей — **`npm ci`**, Node.js 24. В переменные не вставляйте пароли или service_role.
5. Запустите публикацию только этого нового приложения. Оно должно получить свой технический адрес **`*.tatnet.app`**. Не подключайте missmaki.ru, www.missmaki.ru или платный собственный домен. Если кабинету нужны дополнительные настройки, передайте только названия полей и текст ошибки без секретов — команда сборки локально уже проверена.
6. На полученном **настоящем** тестовом адресе откройте **`/setup/`**. Вставьте ваш Project URL и публичный anon/publishable key → «Сохранить настройки». При публикации из архива они уже включены и повторный ввод не нужен. Если отправка гостевого заказа сообщает об отсутствии модуля 003, сначала нужна миграция; RLS отключать нельзя.
7. Перейдите по ссылке **«Войти в кухню»** → введите почту и пароль созданного тестового администратора → «Войти». Если данные верны, но нет staff, панель сообщит об отсутствии прав. Не создавайте повторно того же пользователя и не назначайте всем роль admin.
8. Нажмите **«Включить звук»**. Проверьте заказы №1/№2 с отметкой «НЕ ГОТОВИТЬ»; их можно отклонить. Затем — «Проверка прав и времени»: новые гостевые тесты доступны после 003. Для проверки магазина откройте `/` на том же тестовом адресе; оформляйте только вымышленные заказы.

При сборке из Git браузерные публичные настройки нужно ввести на каждом устройстве. Архив, подготовленный отдельно с этими значениями, уже содержит их. Пароль в архив не включается. Если телефон общий, завершайте работу кнопкой «Выйти».

Статический сайт не запускает дополнительный backend. Сам Татнет описывает бесплатный тариф для экспериментов и выдачу технического HTTPS-домена: [тарифы](https://tatnet.ru/pricing), [публикация приложений](https://docs.tatnet.ru/docs/platform/apps). На Free возможен бейдж провайдера и действуют его лимиты. Платный тариф не выбран; отсутствие тестовой ссылки не означает, что сайт уже опубликован.

## После входа

iPhone/iPad: Safari → «Поделиться» → «На экран Домой». Пользуйтесь только тестовым адресом. Звук разрешается вашим нажатием и не гарантируется при закрытой вкладке/заблокированном экране. До физического испытания на вашем устройстве мы не считаем эти функции проверенными.
