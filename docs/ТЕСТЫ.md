# Отчёт о проверке — 1 ноября 2026

## Выполнено локально

`npm test`: **12 / 12 успешно**. Реальные SQL-миграции исполняются в PGlite (PostgreSQL в WASM), auth.uid и роли Supabase моделируются тестовой схемой.

1. Создание заказа и повтор после потерянного ответа; то же тело из другой вкладки с другим request_id возвращает прежний заказ. Изменённое тело с уже использованным ID отклоняется.
2. Сервер отклоняет поддельные цены, SKU, количество и повторную бронь слота предзаказа; занятое время даёт три свободные альтернативы.
3. Покупатель не видит чужой заказ, не меняет статус и не назначает себе роль сотрудника.
4. Все **8** вариантов времени (15, 30, 45, 60, 90, 120, 150, 180), отказ, недопустимое время и устаревшая версия заказа.
5. Разные заказы получают разные номера; параллельно запущенные повторы одного ID возвращают одну запись. Это однопроцессная PGlite-проверка: настоящая конкуренция отдельных серверных соединений ещё требует приёмки.
6. Отзыв требует отдельного согласия, повтор не дублируется, автор не может опубликовать его сам.
7. Принятый отзыв появляется публично. Отклонённый исчезает из публичного RPC и прямого SELECT другого покупателя, внутренний статус rejected сохранён, автор видит pending после повторного входа в тестовую сессию. События модерации сохранены.
8. Роль anon не читает персональные данные и не вызывает административные функции.
9. Цены и SKU SQL-каталога совпадают с текущим меню index.html.
10. Скрипт переключения на временной копии удаляет старый транспорт, сохраняет меню и фотографии, не принимает secret key. Включённый HTML проходит синтаксический разбор JS. Использованные URL/ключи — только явные тестовые fixtures, они не являются рабочими настройками.

11. Одновременные первые действия покупателя используют одну anonymous sign-in сессию, не создавая конкурирующие UID.
12. Зависший HTTP-запрос прерывается таймером; внешняя отмена запроса также передаётся в fetch.

`npm run test:browser`: **15 / 15 успешно** в Chromium, по 5 сценариев на размерах iPhone 13, iPad и desktop:

- Панель сотрудника, все кнопки времени, отказ, принятие/отклонение отзыва, отсутствие горизонтального переполнения.
- Посетителю без роли панель с данными недоступна.
- Предупреждение при ошибке API и восстановление соединения.
- Автоматическое появление времени у покупателя, сохранение ожидания у автора отклонённого отзыва после reload. В новом пути не было запросов Google Apps Script или Telegram.
- После потерянного ответа черновик восстанавливает имя и корзину; повтор использует прежний request_id. Сверка с тестовым сервером может подтвердить сохранённый заказ даже после ошибки отправки — это корректное восстановление, а не ложное подтверждение.

Браузерные тесты используют **явный fake API**. Это проверка интерфейса и протокола, а не сквозной тест развёрнутого Supabase. Профиль iPhone здесь означает размеры и параметры эмуляции Chromium, **не настоящий Safari**.

Проверены `node --check` для JS и доступность закреплённой CDN-библиотеки Supabase. Добавлен GitHub Actions workflow с такими же автоматическими проверками. Локальные результаты не означают, что workflow уже успешно завершился в GitHub.

## Не проверено и не запущено

- Настоящий проект Supabase отсутствует в настройках задачи. Миграции, Auth, RLS через реальный PostgREST, Realtime/WSS, сетевые задержки и конкуренция нескольких серверных соединений не проверены в развёрнутом проекте.
- Реальный Turnstile: аккаунт, домены и серверный секрет не настроены.
- Физические iPhone/iPad/Android, Safari, звук, установка PWA, блокировка экрана и перезапуск устройства.
- Фоновые push-уведомления не реализованы; гарантированного фонового звука нет.
- Резервные копии, восстановление production, непрерывность тарифа, мониторинг и автоматическое удаление/обезличивание ПД не настроены.
- Самостоятельный сервер Supabase в РФ не развёрнут; вопрос локализации ПД должен быть решён до реальных заказов.
- Фото отзывов не подключены; форма раньше не отправляла отзывы вообще. Работает предусмотренный заданием текстовый состав отзыва.
- Переключение missmaki.ru и отключение старого Apps Script / Telegram-обработчика не выполнены. Для безопасного переключения есть отдельный скрипт и инструкции.
