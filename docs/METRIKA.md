# Метрика 114705499

База отката до изменения: `1cf49b4e456b964261e80385f37b2ba2e2189497`.

Счётчик только на `/` и `/index.html` основного клиентского сайта (missmaki.ru / www.missmaki.ru), только в верхнем окне. Тестовые домены не запускают счётчик. Локальные браузерные тесты требуют явный MM_ANALYTICS_TEST=true и перехватывают tag.js, не обращаясь к настоящему счётчику. Кухня, её резервные/служебные страницы и iframe киоска исключены. Код РСЯ и ads.txt не изменяются.

## Согласие и данные

Отдельное явное согласие на аналитические cookies, срок выбора 180 дней. Рекламное согласие не включает Метрику. До согласия нет загрузчика, пикселей или передачи событий. Noscript-пиксель намеренно не добавлен. Вебвизор выключен явно. После отзыва вызывается destruct, наши события прекращаются. Повторное разрешение после отзыва применяется при новом открытии страницы: повторной инициализации и повтора старого dataLayer на той же странице нет. Страница заказа никогда не обновляется автоматически.

Перед загрузкой удаляются произвольные query и hash из URL через history.replaceState, реферер передаётся только как origin. Это намеренно исключает передачу возможных контактов в параметрах URL; UTM-атрибуция параметров и исходные пути рефереров в этой реализации не сохраняются. При невозможности очистки URL счётчик не запускается. Инициализация использует defer:true, после неё один явный hit с очищенным URL. Нельзя в дальнейшем передавать в ym URL/параметры из форм, UserID, контакты, комментарии или полный объект заказа.

Товарные поля берутся из белого списка существующего меню по SKU, а не из имени автора/комментария/произвольного server item.name. События не содержат номера заказа, request_id, UID покупателя, даты/времени/адреса получения, имени, телефона и комментария. Серверные total/items читаются существующим защищённым запросом только своего заказа, без изменения SQL/RLS.

Ledger IndexedDB содержит внутренний идентификатор запроса, тип заказа, этап и время для дедупликации; наружу идентификатор не передаётся. Старые записи очищаются при открытии БД после 180 дней. Read/write транзакция атомарна между вкладками. Если IndexedDB недоступна, события заказов пропускаются, чтобы не создавать повторов; оформление заказа продолжает работать. Оплата, блокировщик, отказ от согласия, закрытие браузера или сеть могут сделать аналитику неполной: это не бухгалтерский реестр и не гарантия exactly-once доставки в Яндекс.

## Электронная коммерция и факт оплаты

`window.dataLayer`: официальные ecommerce `detail` (видно не менее 50% карточки), `add`, `remove`. Передаются SKU, название варианта, категория, цена и количество. Просмотры SKU дедуплицируются в пределах вкладки/sessionStorage, включая обновление страницы. Действия с корзиной отражают реальное увеличение/уменьшение количества; очистка после отправки не считается удалением пользователем.

Начало оформления, успешное сохранение, выбранный способ и решение кухни — custom события dataLayer и JavaScript-цели. Начало — первое взаимодействие с непустой корзиной в рамках попытки оформления. События после заказа требуют существующей попытки с согласием; старые заказы в истории не отправляются задним числом. Отметка is_test исключает обработку решения кухни.

**`ecommerce.purchase` не отправляется.** В текущей базе нет достоверного признака оплаты на кассе. Принятие, завершение приготовления и оплата — разные факты. При принятии в цель `mm_order_confirmed` передаются серверная сумма как `order_price` и `confirmed_total`, валюта RUB и `payment_status: not_verified`. При неполных серверных данных подтверждение без проверенной суммы не отправляется. Это стоимость исторически подтверждённых заказов, НЕ фактически оплаченная выручка. Отказ — отдельная цель без дохода. Если решение позже изменено, оба факта остаются в целях; подтверждение не превращается в оплаченную продажу. Повторное подтверждение того же заказа не добавляет сумму второй раз.

Средняя сумма подтверждения: доход **только цели mm_order_confirmed / число её достижений**, с названием отчёта «Средняя сумма подтверждённых заказов — оплата не проверена». Оплаченный средний чек и финансовый ecommerce purchase можно подключать только после появления доверенного события оплаты/возврата. Не интерпретировать общий доход по всем целям как оплаченные продажи.

`mm_confirmed_item` содержит отдельную строку подтверждённого заказа: product_id, product_name, category, price, quantity, order_type и payment_status. Для популярности подтверждённых роллов/сетов/дополнений суммировать quantity по SKU этой цели; detail/add/remove доступны в ecommerce. Устаревшие/неизвестные SKU пропускаются.

## Однократно в кабинете владельца

Доступа к кабинету Метрики у агента нет; создание целей или включение опций в кабинете не заявляется выполненным.

1. Метрика → счётчик **114705499** → Настройка → Электронная коммерция: включить сбор, контейнер **dataLayer**, если ещё не включено. Не включать Вебвизор и сбор контактных данных.
2. Цели → Добавить цель → **JavaScript-событие**. Создать следующие идентификаторы (дополнительные автоматические ecommerce цели не заменяют их):

| Идентификатор | Название |
|---|---|
| `mm_checkout_started` | Начало оформления |
| `mm_delivery_order` | Отправлен обычный заказ с доставкой |
| `mm_pickup_order` | Отправлен обычный самовывоз |
| `mm_preorder_delivery_order` | Отправлен предзаказ с доставкой |
| `mm_preorder_pickup_order` | Отправлен предзаказ на самовывоз |
| `mm_order_submitted` | Заказ сохранён сервером |
| `mm_order_confirmed` | Подтверждён кухней — оплата не проверена |
| `mm_order_rejected` | Отклонён кухней |
| `mm_confirmed_item` | Товар подтверждённого заказа — оплата не проверена |

События — не факт оплаченной покупки. Доход передаётся только для подтверждения, не для отправки, типов получения, отказа или товаров (чтобы не суммировать его несколько раз).

## Проверка и откат

Тесты подменяют tag.js локальным recorder; фиктивные заказы не отправляются в настоящий счётчик. Проверяются типы заказов, сумма с сервера, отсутствие purchase, дедупликация между вкладками/перезагрузками, очистка URL, whitelist полей, cookies, блокировщик и исключённые интерфейсы. End-to-end использует локальную PostgreSQL/PGlite, рабочая база не меняется.

Для быстрого отключения удалить только подключение shared/analytics.js из head, оформить отдельный commit/PR и опубликовать main/root. Опциональные хуки в customer.js безопасны без этого скрипта. Для полного отката revert merge-коммита этого PR (`git revert -m 1 <merge_sha>`), без reset/force push и без отката последующих изменений. База не требует миграции или восстановления.
