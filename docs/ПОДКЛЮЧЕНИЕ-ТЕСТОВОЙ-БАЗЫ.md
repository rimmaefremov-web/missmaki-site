## Куда безопасно вставить настройки с iPhone

В подготовленном для владельца архиве публичные настройки уже вставлены; повторно вводить их не требуется. Если нужны изменения, в отдельной тестовой сборке есть страница **`/setup/`**, с двумя полями:

1. **Project URL** — значение из Studio → Project Settings → API.
2. **Публичный anon key** — из того же раздела.
3. Нажмите **«Сохранить настройки»**, затем **«Войти в кухню»**.
4. В кухне введите почту и пароль созданного тестового сотрудника. Пароль идёт только в Auth выбранного проекта по HTTPS; в чат его не присылайте.

Страница `/setup/` находится в подготовленной сборке; **публичная тестовая HTTPS-ссылка пока не опубликована**. Не открывайте и не создавайте `/setup/` на рабочем missmaki.ru. Для iPhone нужна отдельная ссылка тестового размещения, открытие архива как локального файла не заменяет хостинг.

Настройки сохраняются только в localStorage браузера на этом тестовом адресе. При сохранении страница ничего не отправляет в сеть, не меняет файлы репозитория и не создаёт базу. На втором устройстве повторите ввод на том же тестовом домене; Safari и установленная PWA могут иметь раздельное хранилище. При смене проекта старые сессии браузера очищаются, чтобы не отправить токен прежнего проекта другому серверу.

URL API и anon key рассчитаны на браузер и не дают прав администратора при правильно настроенной RLS. `service_role`, `sb_secret_…`, пароль Studio и пароль базы в эти поля вставлять нельзя; форма отсекает служебные ключи. Секреты не должны попадать ни в ChatGPT, ни в GitHub. Пароль сотрудника вводится только в форме входа на известной тестовой HTTPS-ссылке.

Если удобнее, можно передать исполнителю **только Project URL и anon key** для включения в тестовую сборку. Это не передача административного доступа. Для проверки действий сотрудника владелец входит локально; пароль передавать исполнителю не требуется.

## Проверка подключения в вашем браузере

1. В тестовой кухне откройте **«Проверка прав и времени»** (`/kitchen/diagnostics.html`).
2. Если вы ещё не вошли — войдите созданной учётной записью. Наличие пользователя не заменяет назначение staff; проверка отдельно вызывает is_staff.
3. Нажмите **«Проверить права и все времена»**. Работайте только с пустой отдельной MissMaki-test, не с копией реальных заказов.
4. Проверка создаст вымышленный предзаказ на завтра, имя **«АВТОТЕСТ MissMaki»**, телефон-заглушка и комментарий **«НЕ ГОТОВИТЬ»**. Настоящие телефон, адрес и имя клиента не используются. Звонки/SMS не отправляются.
5. В отчёте будут: вход сотрудника; независимые анонимные покупатели; запись и повтор запроса; изоляция чужого заказа; запрет клиентского RPC и прямого изменения таблицы; проверка цены; **15, 30, 45, 60, 90, 120, 150, 180 минут**; отказ и история.
6. Тестовый заказ останется **отклонённым**; запись и журнал не удаляются. Если проверка оборвалась и завершить отказом не удалось, в отчёте будет предупреждение: найдите «АВТОТЕСТ» в кухне и отклоните его. Проверка никогда не редактирует ранее существовавшие заказы.
7. Нажмите **«Скопировать отчёт без ключей и паролей»** и передайте результат. В отчёт не включаются почта, пароль, JWT, ключи, данные существующих заказов и ID пользователя.

Если anonymous sign-in отключён, обычная проверка остановится на создании покупателей. Для независимого прогона SQL-пути можно отметить флажок использования двух вымышленных тестовых учётных записей. В отчёте будет явно указано, что гостевое оформление не проверено. Этот режим не меняет авторизацию посетителей магазина. Не отключайте RLS и не выдавайте всем доступ к таблицам. Настройка anonymous у Татнет всё ещё требует проверки; при отсутствии переключателя нужно уточнить поддержку у провайдера. Ошибки прав или несовместимости API — это непройденная проверка, а не основание считать интеграцию работающей.

Серверные кнопки проверяются реальными RPC только после запуска на вашей базе. Предварительно тот же диагностический сценарий проверен локально на SQL-миграциях в PGlite; это не проверка вашего Татнет.

Затем вручную: магазин на iPhone → вымышленный заказ → кухня на планшете → кнопка времени → ответ на iPhone без обновления. Отдельно проверить звук и разрыв связи. Диагностика чтения статуса через REST не доказывает работу Realtime/WebSocket, доставки звука или Safari на физическом устройстве.

## Для исполнителя: сборка без настроек и без публикации

```sh
node scripts/build-russian-preview.mjs --setup --output /tmp/missmaki-test-preview
```

Копия содержит `/setup/` и диагностику. Встроенная конфигурация выключена и пуста. После локального сохранения двух публичных значений включается только тестовая копия. На `missmaki.ru` и `www.missmaki.ru` такая локальная настройка запрещена. Этот запрет не заменяет отдельное размещение.

Для публикации нужен отдельный HTTPS-хостинг тестовой копии; его доступ в задаче не предоставлен. Не менять CNAME или DNS рабочего сайта, не объединять PR. Настройку Project URL/anon key в основной shared/config.js не выполнять. Опубликовать статический экспорт можно после получения технического доступа к отдельному тестовому размещению. Вся папка экспорта должна лежать в корне этого тестового origin, чтобы работали /kitchen/, /setup/ и PWA scope.
