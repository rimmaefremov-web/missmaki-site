1. СКАЧАТЬ
Нажмите ZIP → «Поделиться» → «Сохранить в Файлы». В «Файлах» нажмите ZIP один раз — появится папка. Начните с этого файла.

2. ПРОВЕРИТЬ ПАКЕТ
site/ — только файлы для GitHub. apps-script/ — только для существующего Google Apps Script «Проект без названия». backup/ — текущие рабочие файлы для возврата, НЕ для обычной установки.
Юридические страницы содержат заметные пометки «Черновик». Их нельзя объявлять окончательными и публиковать без заполнения и проверки. Адрес ИП не выдуман. ФИО, ИНН, ОГРНИП и email уже внесены.
В отдельном файле BEFORE-PUBLISH.txt перечислено, что необходимо уточнить.

3. GITHUB — СНАЧАЛА ОТДЕЛЬНАЯ ВЕТКА, БЕЗ ПУБЛИКАЦИИ
В Safari откройте github.com/rimmaefremov-web/missmaki-site → переключатель main → создайте ветку missmaki-confirmation-review-2026-10-28. В ней Add file → Upload files → Choose your files → «Обзор». Выберите 5 файлов ВНУТРИ site/: index.html, seller.html, privacy.html, consent.html, terms.html. Загрузите в корень новой ветки и подтвердите commit в эту ветку. При необходимости включите «Запросить настольный веб-сайт» в меню Safari.
Не загружайте всю папку site вложенной папкой. Не удаляйте CNAME, README.md, test и другие файлы. Не меняйте GitHub Pages и не объединяйте ветку с main сейчас.
Если GitHub показывает 403, сначала проверьте вход в аккаунт с правом записи в этот репозиторий. Ошибка подключения Codex не обязательно означает отсутствие прав у владельца. При запрете настройки конкретной интеграции требуется Repository permissions → Contents: Read and write для этого репозитория; права Pages для подготовки ветки не нужны. Не передавайте пароли или токены.
Если создать ветку с iPhone не удаётся — остановитесь: файлы уже готовы, действующий сайт не затронут.

4. APPS SCRIPT — ТОЛЬКО ПОСЛЕ ОТДЕЛЬНОГО СОГЛАСОВАНИЯ
Никаких изменений в рабочем проекте сейчас. Сначала нужна ваша отдельная команда на замену кода и обновление существующего deployment.
После согласования: в проекте «Проект без названия» заменить содержимое существующих Код.gs и AvailabilityFix.gs ПОЛНЫМИ файлами из apps-script/. Новые дубликаты файлов или функций не создавать. Изменение AvailabilityFix.gs нужно для проверки закрытого ключа статуса; расчёт свободного времени сохранён.
Весь текст готов: искать/править отдельные строки не нужно. Если TXT/HTML не копируется в Safari на iPhone, попросите прислать Код.gs целиком в одном сообщении, затем AvailabilityFix.gs отдельным следующим действием. Не используйте старый файл из предыдущего архива.
BOT_TOKEN и CHAT_ID оставить как есть. Свойства проекта не очищать. Не запускать setup/testTelegram без необходимости. В проект MissMaki — ТЕСТ эти файлы НЕ ставить.
Apps Script API сам по себе не предоставляет Codex авторизацию к вашему проекту; автоматической установки без вашей учётной записи в этой сессии нет.
После вашего разрешения: «Развернуть» → «Управление развёртываниями» → существующее веб-приложение → карандаш → «Новая версия» → «Развернуть». Сохранить прежний адрес /exec. Не создавать новое развёртывание. Выполнение — от владельца, доступ — всем, включая посетителей без входа в Google; иначе Telegram не сможет отправлять POST.
Сервер совместим со старой формой заказа: отсутствие нового поля consent не ломает старых клиентов. Но старый клиент не умеет сохранять закрытый ключ статуса новых заказов. Поэтому переход к новой странице нужно согласовать в спокойное время и проверить одним контролируемым заказом; нельзя обещать показ новых статусов в старой открытой вкладке.

5. TELEGRAM — ОТДЕЛЬНЫЙ СОГЛАСОВАННЫЙ ШАГ
Сначала в редакторе выбрать mmCheckProductionWebhook → «Выполнить». Это только чтение getMe/getWebhookInfo, заказ не отправляется, webhook не меняется. В журнале безопасные флаги, без токенов и секретного URL.
botIsProduction должен быть true. При hasWebhook:true и pointsToThisDeployment:false НИЧЕГО НЕ ПЕРЕПОДКЛЮЧАТЬ автоматически: сначала нужно проверить существующую интеграцию. mmConnectProductionWebhook в этом случае специально остановится, не заменив её.
Если webhook отсутствует либо уже принадлежит этому модулю, только после отдельного разрешения выполнить mmConnectProductionWebhook. Она проверит бота @MissMakiBot, точный production URL, доступность опубликованного doPost и затем подключит callback_query/message, НЕ удаляя ожидающие обновления. Тестовый @MissMaki_Test2026_bot не затрагивается. Никаких ссылок с токенами вручную вводить не нужно.
Новый секрет MM_CONFIRM_HOOK_KEY создаётся сервером. Не публиковать свойства проекта и полный webhook URL. BOT_TOKEN и CHAT_ID не меняются. Ответ на /start эта доработка не добавляет: обычные сообщения подтверждаются без создания заказов.
Нажимать кнопки могут создатель/администраторы группы «MissMaki Заказы». Проверка Telegram getChatMember для других участников надёжно работает, если бот является администратором группы. Достаточно минимально необходимых прав; назначьте принимающим заказы сотрудникам роль администратора группы. Без успешной проверки прав решение не сохраняется.
Старые сообщения в группе не получают кнопки задним числом.

6. КОНТРОЛЬНАЯ ПРОВЕРКА ПОСЛЕ СОГЛАСОВАННОЙ УСТАНОВКИ
Открыть новую страницу в Safari после разрешённой публикации/подключения. Добавить один товар; имя «ТЕСТ — НЕ ГОТОВИТЬ», телефон/адрес с явной пометкой «НЕ ЗВОНИТЬ / НЕ ДОСТАВЛЯТЬ», комментарий «ТЕСТ, не реальный заказ». Если форма позднее начнёт проверять формат телефона, использовать согласованный номер владельца, не чужой.
Отметить согласие самостоятельно. Отправить ОДИН раз. Не проводить оплату. Дождаться «Ваш заказ отправлен!» и сообщения с тем же номером в группе. Пустая корзина сама по себе недостаточна.
Администратор нажимает «60 мин». На той же странице без перезагрузки должно появиться «✅ Ваш заказ принят! Начинаем готовить. Ориентировочное время ожидания — 60 минут» (обычно в пределах следующей проверки, интервал 12 секунд плюс ответ сервера). Повторное нажатие/доставленный повторно callback решения не меняет. После перезагрузки результат сохраняется.
Предзаказ и отклонение проверить отдельными заранее согласованными помеченными тестовыми заявками. Отклонённый предзаказ освобождает слот; принятый сохраняет занятость.
При временном сбое проверки статуса не отправлять заявку повторно — сайт продолжит проверку, сохраняя известный результат. При неопределённом ответе отправки корзина сохраняется; сначала сверить номер с группой. Сервер не пересылает повторно тот же requestId.
На настоящем iPhone отдельно проверить звонок, доступность корзины над нижней панелью и сохранение результата после закрытия/открытия Safari. Проверка Linux WebKit не заменяет эту проверку.

7. ОТКАТ
Не удалять новые записи заказов или Script Properties. После согласования можно вернуть site/index.html из backup и предыдущую версию существующего веб-развёртывания. Подключённый новый webhook нельзя оставлять направленным в старый doPost, который не обрабатывает callbacks: остановить откат до согласования возврата webhook. Не вызывать deleteWebhook вслепую и не очищать pending updates. При возврате сайта юридические новые файлы могут остаться, удалять их не требуется.

Публикацию и действия под аккаунтами можно провести с сопровождением по одному короткому действию. Этот файл описывает весь порядок, а не разрешает выполнить всё сейчас.
